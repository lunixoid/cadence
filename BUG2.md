# BUG2 — иногда «квакает» звук при воспроизведении

**Статус: DONE** (1.27.0, 2026-08-14). Пользователь подтвердил, что на новых стримовых треках в shuffle квака больше нет. Если повторится — открыть снова.

Симптом: точечные пролаги / «кваканье» на 1–2 с, на разных треках и таймкодах. Не битый файл в смысле «другой плеер играет нормально»: те же треки из «Скачанное» в VLC/ffmpeg звучат чисто.

Движок: `AVAudioEngine` + `AVAudioPlayerNode`, PCM чанками ~1 с (не `AVPlayer`). Декод MP3 — `AVAudioFile` (AudioToolbox).

Чаты: [Пролаги и спектр](4ceb1d93-6aa8-456d-b69a-69d42a9785ad), [Лимитер и содержимое](264d663e-1088-4e1e-8304-9b2ad3441bde).

## Что починили

Корень — **S**: порча MP3 при **потоковой** записи. «Скачанное» (`URLSessionDownloadTask`) всегда писало файл по порядку; стрим — нет.

1. **Порядок чанков.** `onData` ходил через unstructured `Task { await appendData }`. Два подряд HTTP-куска могли записаться наоборот → дыры в bitstream (часто ≈ один кадр 320 kbps).
2. **Retry + HTTP 200.** Range-повтор, на который сервер отвечал полным телом (200 вместо 206), **дописывался** после уже скачанного куска.

Слышимый «квак» — **R**: Apple MP3-декодер на gap вставляет тихую гранулу 1152 сэмпла (~26 ms), IIR EQ звенит. ffmpeg тот же файл играет без нулей (`Header missing`).

Правки в 1.27.0:

- `ProgressiveFileWriter` — запись HTTP-тела на serial queue, без Task-hop на каждый чанк.
- HTTP 200 на ranged retry → truncate и запись с нуля.
- Concealment тихих гранул 576–2304 сэмпла (не паддинг начала/конца) — защита уже лежащих в кеше дырявых файлов.

Отладочная инструментация снята.

## Методика, если снова воспроизведётся

- **Не перепроверять закешированный трек** — он мог быть записан старым стримером.
- Новый трек (ещё не в кеше) в shuffle; если квак — сразу стоп, не давать gapless подложить следующий из кеша.
- «Скачанное» vs тот же трек потоком.

## Доказательства (кратко)

Трек `E8FA5E21-….mp3`: три MPEG-gap на 02:44.68 / 02:45.09 / 02:45.49. `afconvert`: 1152 нулей в 02:45.500. `ffmpeg`: нулей нет. В кеше десятки таких файлов (кластер `84/878/84` байт ≈ кадр 320 kbps).

Наблюдение пользователя: «Скачанное» всегда ок; один и тот же трек потоком то ок, то нет. Не перепроверять кеш.

v9: свежий `440A895F` без gap на 02:42; квак с высокой вероятностью на gapless-следующем из кеша.

## Что не делать снова

- Не списывать на сеть / underrun / refresh / config / спектр / лимитер / стык 1 с чанков без новых улик.
- Не считать «другой плеер играет» доказательством, что Apple-декод этого файла без дыр.
- Не проверять фикс на закешированном треке.
- Concealment — не лечение корня; корень — как стрим пишет файл (S).
